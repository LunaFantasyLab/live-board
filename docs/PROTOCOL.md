# 数据格式与 Notion 协议

写入端和 Mac App 之间只通过你 Notion 里的一张表「看板数据」交换数据。双方都只用 Notion 公开 API（`Notion-Version: 2022-06-28`）。

## 「看板数据」表

| 列 | 类型 | 说明 |
|---|---|---|
| 名称 | 标题 | 事件行：事件 ID；名单 / 工位行：`名单` / `工位`；换人行：`换人 <时间>` |
| 类型 | 单选 | `事件` / `工位` / `名单` / `换人` |
| 序号 | 数字 | 写入端分配，只增不减；看板靠它增量读取 |
| 数据 | 文本 | 一段 JSON（超过 1000 字会切成多段文本，读时拼回去） |
| 状态 | 单选 | 只给换人行用：`待处理` / `已处理` / `已拒绝` |

谁写什么：

| 行 | 谁写 | 怎么写 |
|---|---|---|
| 事件 | 写入端 | 每条打卡一行，只追加 |
| 名单 | 写入端 | 只有一行，名单变了就更新这一行（序号换新） |
| 工位 | 写入端 | 只有一行，工位变了就更新这一行（序号换新） |
| 换人 | Mac App | 每次换人加一行「待处理」；写入端核对后改成「已处理」或「已拒绝」，并归档 |

看板的读法：第一次全量读；之后每次只读 `序号 > 已读最大序号 - 50` 的行（留 50 的余量，防止 Notion 新行稍晚才能查到）；
每 15 分钟额外问一次最新的名单行和工位行（按序号倒序，只取 1 行），防止漏掉。

## 事件（events.jsonl 的一行，也是事件行的「数据」）

```json
{"v":1,"id":"01J…","ts":"2026-01-31T09:05:00+00:00","bot":"研究员","type":"接单","project":"示例任务",
 "task_id":null,"to":null,"gate":null,"message":"收到，开始找资料","files":[],"source":"cli"}
```

| 字段 | 说明 |
|---|---|
| `id` | 唯一 ID（时间有序），写入端去重用 |
| `ts` | 带时区的时间 |
| `bot` | 成员名，必须在名单里 |
| `type` | 接单 / 开始 / 产出 / 交接 / 退回 / 待确认 / 完成 / 报错 |
| `project` | 任务名（可空），看板按它归组显示进度 |
| `to` | 交接、退回的接收人 |
| `gate` | 可选的短标记（字母数字，最多 16 个字符） |
| `message` | 一句话，最多 80 个字；像密钥的内容会被拒收 |
| `files` | 只记文件名，不记路径 |
| `source` | `cli`（打卡）或 `backfill`（补记） |
| `test` | 为 `true` 时只留在本机，不同步、不显示 |

## 名单（roster.json，也是名单行的「数据」）

见 [examples/roster.example.json](../examples/roster.example.json) 和 [examples/README.md](../examples/README.md)。可选字段 `notice`：一行提示，会显示在看板顶部。

## 工位（state/slots.json，也是工位行的「数据」）

```json
{"slots":["调度","研究员","写手","画师","剪辑师","审核员"],"updatedAt":"2026-01-31T10:00:00+00:00","by":"手动替换"}
```

## 换人行的「数据」

```json
{"slots":["调度","研究员","写手","画师","剪辑师","数据员"],"ifEmpty":false,"reason":"manual","at":"2026-01-31T10:00:00.000Z"}
```

写入端的处理：6 个名字必须不重复且都在名单里，否则「已拒绝」；`ifEmpty` 为 true 且已经有工位时保持不变。
Mac App 写完换人行后，最多等 60 秒；这段时间里没等到新的工位行，看板会退回原来的工位并提示写入端好像没在运行。

## Mac App 原生层放行的请求

看板网页（relay.js）：

- `POST /v1/databases/{本表}/query`
- `POST /v1/pages`：只能在本表里建「类型 = 换人」的行

设置窗口（setup.js），每次打开设置窗口都从零开始，随向导一步步放开：

- `GET /v1/users/me`（验证密钥）
- `POST /v1/search`：只能带「只要页面」的过滤（`filter.property = object`、`filter.value = page`），列不出任何表
- `POST /v1/pages`：父级必须是刚才列出来的页面，且不能带正文内容（用来建「实时看板中转」页）
- `POST /v1/databases`：父级必须是向导刚建的中转页，且不能带正文内容
- `GET /v1/databases/{id}`：只能读向导刚建的那张表，或用户粘贴链接选定的那一张（换一张就替换掉上一张）
- 点「完成」时也只接受这张表；先写设置，再保存密钥，密钥存不进去就把设置退回原样
- 密钥文件先写同目录临时文件（权限 600），再原子替换

其他请求一律拒绝。规则写在 `app/LiveBoard/Policy.swift`，测试在 `tests/swift/main.swift`。

## 速率

Notion 的限制约为平均每秒 3 次。写入端两次请求至少隔约 0.45 秒，遇到 429 按 `Retry-After` 等待后重试；
看板和设置窗口两次请求至少隔 350 毫秒，遇到 429 或 5xx 最多重试 3 次。
